# Дружба · Календарь ресторана

Рабочая начальная версия приложения для ресторана при гостинице в Выборге. Устанавливаемое веб-приложение (PWA) с одной общей базой, интерфейсом для компьютера и телефона и одной общей учётной записью. Зал 1 — 72 гостя, зал 2 — 55 гостей.

## Тестовая версия для заказчика на GitHub Pages

Ссылка для тестирования: [открыть календарь «Дружба»](https://koopin66.github.io/druzhba-calendar/).

Демонстрационная сборка находится в `docs/`. Она работает без Python и общей серверной базы. Заявки, настройки залов и история сохраняются только в localStorage браузера на конкретном устройстве. Используйте вымышленные контакты. На другом устройстве будет отдельный календарь; очистка хранилища браузера удалит записи. Доступ к демоверсии свободный, пароль не требуется.

Календарь начинается пустым. Обновление от 5 ноября 2026 года один раз удаляет все заявки из прежней версии демонстрации при открытии обновлённого приложения, сохраняя настройки залов. Созданные после этого новые заявки сохраняются при перезагрузке. В настройках есть действие «Очистить календарь», которое также сохраняет залы и не добавляет примеры.

Заказчику достаточно открыть ссылку GitHub Pages. Для установки: Android — Chrome → меню → «Установить приложение»; iPhone — Safari → «Поделиться» → «На экран Домой»; ПК — установка приложения в Chrome/Edge. Кнопка «Как установить» есть в интерфейсе. Манифест, иконки и service worker поддерживают размещение в подпапке репозитория.

После одобрения интерфейса размещается серверная версия: она использует ту же основу интерфейса, проверку бронирований на сервере и общую базу. Существующие тестовые записи автоматически в рабочую базу не переносятся.

Пересборка демоверсии после изменения исходников:

```powershell
python build_demo.py
node --test tests/demo.test.cjs
python -m unittest discover -s tests -p test_demo_build.py
```

Для локального просмотра статической сборки: `python -m http.server 8777 --bind 127.0.0.1`, затем открыть `http://localhost:8777/docs/`. GitHub Pages публикует папку `/docs` ветки `main`. Не направляйте Pages на корень репозитория: там находятся исходники серверной версии.

## Быстро посмотреть на Windows

Нужен установленный Python 3.11 или новее. Библиотеки устанавливать не требуется.

1. Распакуйте архив целиком.
2. Дважды нажмите `Demo.cmd`.
3. В браузере откроется `http://localhost:8766/?demo=1` с вымышленными мероприятиями.
4. Оставьте окно сервера открытым. Для остановки нажмите Ctrl+C в нём.

Если браузер не открылся, перейдите по адресу вручную. Запуск через терминал:

```powershell
python server.py --demo --port 8766
```

## Рабочая база на этом компьютере

Запустите `Start.cmd` или:

```powershell
python server.py
```

Откройте `http://localhost:8765`. Логин `admin`, случайный начальный пароль будет один раз показан в окне сервера. Смените его в настройках и передайте команде. Если пароль нужно задать до самого первого запуска, используется переменная среды `DRUZHBA_ADMIN_PASSWORD` (минимум 12 символов). После создания базы она пароль не меняет.

Демо использует `data/demo.sqlite3`, рабочий режим — `data/calendar.sqlite3`. Рабочая база при первом запуске пустая; вымышленные заявки в неё не попадают. Не удаляйте папку `data`. На устройстве клиента не хранится копия бронирований; при недоступном сервере просмотр текущих данных и создание заявок требуют восстановления связи.

Локальный адрес работает только на этом ПК. Для совместной работы и установки на телефон нужен общий HTTPS-адрес: см. [размещение](deploy/README.md). Сервер, домен, сертификат на реальном домене и установка на физических телефонах пока не настроены.

## Что работает

- Календарь месяца, недели и дня; переход к любому месяцу.
- Карточки групп, банкетов и других мероприятий: дата, начало/окончание, зал, гости, контакты, комментарий.
- Создание, редактирование, подтверждение, отмена и повторное подтверждение заявки.
- Проверка доступности одновременно во всех залах.
- Общие группы занимают места; опция «Зал целиком» блокирует пересекающиеся мероприятия.
- Предварительные заявки резервируют места; отменённые не занимают места.
- Проверка пикового числа гостей на пересекающихся интервалах, а не простое суммирование всех гостей за день.
- Сохранение проверяется сервером в одной транзакции: параллельные запросы не обходят вместимость.
- Защита от перезаписи новой версии заявки старой открытой карточкой.
- Общая сессия входа на каждом устройстве, смена общего пароля, история изменений.
- Настройки залов, поиск, фильтры, выгрузка в CSV и резервная копия SQLite.
- Обновление изменений с сервера каждые 15 секунд и при возвращении в приложение.
- Локальный шрифт, иконки, манифест и service worker для установки без магазинов.

Все даты и время трактуются как московское время ресторана (UTC+3), независимо от местонахождения менеджера. Если банкету нужны подготовка и уборка, включите их в интервал бронирования. Интервалы могут переходить через полночь, максимум 48 часов.

При общем логине невозможно различить людей в истории. Заявки видит каждый, кому передан общий пароль. Нельзя заводить локальный сервер с отдельной рабочей базой на каждом устройстве и ожидать синхронизации между ними.

## Проверка

```powershell
python -m unittest discover -s tests -v
node --check public/app.js
```

Автоматические проверки покрывают вместимость, соседние интервалы, параллельную запись, отмену, конфликт редактирования, авторизацию, резервную копию, CSRF и файлы PWA. Проверка реальной установки и внешнего сервера выполняется после размещения. Node нужен только для проверки синтаксиса, не для запуска.

Резервная копия локальной рабочей базы:

```powershell
python backup.py
```

Скрипт проверяет целостность копии и очищает сессии из неё. Храните копии вне компьютера с сервером. Кнопка резервной копии в интерфейсе сохраняет полный снимок, включая сессии, поэтому при восстановлении их нужно очистить.
