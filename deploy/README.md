# Размещение общего календаря

Для удалённой работы выбирайте один общий сервер, а не отдельную базу на каждом устройстве. Рекомендуемая начальная конфигурация: VPS в России, 1 ядро, 2 ГБ RAM, 15–20 ГБ SSD/NVMe, Ubuntu 24.04 LTS, публичный IPv4. Для небольшой команды ресторанного календаря это предварительная техническая оценка; нагрузочные испытания не проводились.

Предварительные варианты размещения: FirstVDS «Старт» в Москве (1 ядро, 2 ГБ памяти) или стандартный сервер VDSina в Москве с 1 ядром и 2 ГБ памяти. Для бюджета разумно заложить 700–1000 ₽/месяц с резервным копированием, домен отдельно. Окончательную конфигурацию и сумму проверьте в панели заказа. Для заявок ресторана нужна ежедневная копия базы вне основного сервера.

Источники: [тарифы FirstVDS](https://firstvds.ru/blog/s-1-iyulya-povysitsya-stoimost), [стандартные серверы VDSina](https://vdsina.ru/pricing/standard). Альтернатива — [Timeweb Cloud](https://timeweb.cloud/services/cloud-servers); стоимость IP и резервных копий проверяйте отдельно.

## Подготовка

1. Оформите VPS и домен на владельца ресторана. Нужен обычный Linux VPS с Docker Compose; PHP-хостинг для этой поставки не подходит.
2. Установите Docker по [официальной инструкции](https://docs.docker.com/engine/install/ubuntu/) или выберите готовый Docker-образ провайдера.
3. Создайте DNS A-запись домена/поддомена на публичный IPv4 сервера. Подойдёт поддомен существующего домена гостиницы, если есть доступ к DNS. Доступность конкретного имени не проверена.
4. Откройте входящие порты 80 и 443; административный SSH ограничьте доверенными адресами. Порт 8765 наружу не публикуется.
5. Скопируйте проект на сервер, например в `/opt/druzhba`. Не копируйте демонстрационную базу.

## Запуск

Из папки проекта:

```sh
cp .env.example .env
```

Замените `calendar.example.ru` в `.env` на реальное имя. Затем:

```sh
docker compose up -d --build
docker compose logs app
```

Сервер один раз выведет `FIRST LOGIN: admin` и `ONE-TIME INITIAL PASSWORD: ...`. Откройте `https://ваш-домен`, войдите и смените общий пароль в настройках. Передайте его только команде ресторана. После смены старый начальный пароль перестанет действовать. Удалите начальную запись журнала при плановом обслуживании, если она больше не нужна.

Caddy автоматически запрашивает и продлевает сертификат HTTPS для указанного домена. DNS и порты должны быть доступны. Конфигурация подготовлена, но на реальном сервере в этой поставке не запускалась.

## Ежедневная копия

Быстрый ручной вариант: «Настройки → Скачать резервную копию». Для ежедневного задания администратору сервера можно добавить в cron (абсолютный путь уточнить):

```cron
0 2 * * * cd /opt/druzhba && /usr/bin/docker compose exec -T app python -c 'import sqlite3; a=sqlite3.connect("/data/calendar.sqlite3"); b=sqlite3.connect("/data/daily-backup.sqlite3"); a.backup(b); b.execute("DELETE FROM sessions"); b.commit(); b.close(); a.close()'
```

Этот пример обновляет одну локальную ежедневную копию. Отдельно настройте выгрузку копии в защищённое хранилище на другом сервере с хранением 7–30 дат. Локальная копия на том же VPS не защищает от потери сервера. Включите мониторинг доступности и диска в панели провайдера. Подключение внешнего хранилища и мониторинга требует доступа к аккаунту и в этой поставке не выполнено.

## Восстановление

Остановите приложение, сохраните текущую базу отдельно, замените `calendar.sqlite3` проверенной резервной копией с теми же правами пользователя `10001`. Старые `calendar.sqlite3-wal` и `calendar.sqlite3-shm` не должны оставаться рядом с восстановленной базой. Перед заменой проверьте точные пути в Docker volume. Перед открытием сервиса удалите строки из `sessions` в восстановленной базе, чтобы потребовался повторный вход. Запустите контейнер и проверьте заявки, вместимость 72/55 и вход.

Не выполняйте `docker compose down -v`: это удаляет том с заявками. Обновление кода: резервная копия, затем `docker compose up -d --build` без удаления volumes.

## Установка на устройства

- Windows: открыть HTTPS-адрес в Chrome/Edge, выбрать установку приложения.
- Android: открыть тот же адрес в Chrome, выбрать «Установить приложение» / «Добавить на главный экран».
- iPhone: открыть тот же адрес в Safari, «Поделиться → На экран Домой».

На всех устройствах используется один общий логин. Обновления исходников применяются на сервере; устанавливать новую версию через магазин не требуется.
